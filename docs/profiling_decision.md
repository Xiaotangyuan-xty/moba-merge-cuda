## 方法

对三个代表配置（C01/C08/C12，BF16、B=1、C=512、K=4）用带 `record_function` 标记的诊断副本做 torch.profiler 分阶段 profiling（warm 元数据，10 预热 + 5 次前反向）。stage CUDA 合计与干净基线墙钟吻合（3.26 vs 3.32、11.15 vs 12.73、48.07 vs 54.15 ms），说明阶段划分覆盖了主要耗时。profiling 运行与正式计时严格分离。

## host 同步与元数据

- warm 路径每迭代：1× `aten::nonzero`（DtoH）+ 3× `aten::item`/`_local_scalar_dense` + 5× `cudaStreamSynchronize`。规模小时这些 host 等待值得后续在 trace 中逐一归因（候选：`if zero_expert_count > 0`、`gate_mask.nonzero` 形状回读等）。
- cold 元数据（C08）：同步次数翻倍；stage1 重建 0.805 ms/iter ≈ 该配置的 6.5%。主稳态实验用 warm 不可变 cu_seqlens；动态实验单列。

## Amdahl 估算（忽略新增成本的上限）

- 路线 A（stage8）：若合并局部快 3×，C12 前反向约省 7.1%、前向约省 17.7%；C01 前反向约省 11.8%。
- 路线 B（stage9）：单独上限 <3.5%（C12 4.9% → 省 ~3.3%），不做主线。
- 路线 C（stage4+5）：C01 上限高（52%）但形状依赖强；C12 18.4%。
- 任何"不重写 FlashAttention"方案的前反向总上限：非 FA 部分合计 ≈ 39.4%（C12）、57%（C08）、~86%（C01）。

## 路线 A 新增成本估算

远端打包行数 M ≈ (K-1)·T·H（B=1 渐近；C12 解析值 M≈761,856 ≈ 2.91·T·H）。逆映射/槽位构建为 O(M) 轻量 kernel（<0.1 ms 量级），相对 5.1 ms 的合并阶段可控。真正风险在实现质量（原子、排序、寄存器压力），以 V2/V3 消融检验。

## 决定

**锁定路线 A：全局 softmax 结果合并的 GPU 优化**（保持两次 FlashAttention 与路由完全不变）。

- 依据：stage8 在全部三个代表配置越过 10–15% 门槛；前向占比 20–28%；合并数学已有独立可验证形式（方案 4.3）；新增映射成本估算可控。
- 暂不做：路线 B（证据不足，作为 A 完成后的可选增量）、路线 C（仅当 A 的 V3 净收益 <3% 或逆映射成本抵消收益时重新评估）、完整稀疏 Attention 重写（不做）。
- 触发改向的证据：V2 kernel-only 已快但 V3 计入映射后净收益消失，或 stage8 份额在更多形状下系统性低于 8%。记录于本文件。

## 正确性基线要求（路线 A 专用）

选块集合与映射逐位一致；O 与全局 LSE 对冻结基线在 FP32 子算子层面 atol=1e-5/rtol=1e-4 起步；完整 BF16 路径沿用官方测试口径；dQ/dK/dV 随机 VJP 对照。反向结构与官方一致（全局 O/LSE 由新合并路径产出，供官方 backward 使用）。

- 合并 kernel 局部潜力 2.6–3.8x 成立；torch 逆映射构建（argsort 等十余次 launch）会把收益全部抵消（方案 4.4 预言的 V2/V3 陷阱实测复现）。
- 原子计数建图 kernel 成本 0.02–0.03 ms，使 stage 净收益成立。原子序仅影响 lane 累加次序（ulp 级波动，按方案 7.4 记录；官方 index_add_ 同样原子不确定）。
- 容量 kmax=K-1 是官方路由的结构性上界（topk-1），原子建图无溢出风险，另有防御性 mask。
- 按 stage8 占比折算的完整路径预期（待 V3 集成验证）：前反向约省 6–12%，前向约省 13–16%。
