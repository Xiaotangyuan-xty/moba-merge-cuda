# 已知限制与适用边界（2026-10-16 更新）

## 支持范围（方案 2.4 主线）

- 单张 A40（CC 8.6）；packed varlen `[T,H,D]`；MHA（Q/K/V head 数相同）；causal、dropout=0
- head_dim 64/128；BF16 与 FP16（FP16 验证于 F03S/F07M/F12L 三代表配置）
- K=1 走官方 fallback（全量 causal FA），行为逐位一致，不混入稀疏加速统计
- 明确不支持：原生 GQA/MQA、decode KV cache、分页 Attention、多 GPU、端到端模型质量、CUDA Graph 全图捕获。不支持输入显式报错（dtype/布局/空序列/非法 cu_seqlens 有测试覆盖）

## 性能结论的边界

1. **收益只在前向**。反向与官方逐行一致，speedup 实测 0.994–1.006（噪声内）。任何"前反向合计"数字都是前向收益被反向稀释后的结果。
2. **收益幅度随形状变化**：fwd+bwd 1.036–1.085（12 核心配置），fwd 1.066–1.308。H=1/小 T 配置收益最小（launch 与索引开销主导）；块越小、top-k 越大、head 越多，合并阶段占比越高，收益越大。
3. **不承诺推广到未测形状**：H=16/32、D≠64/128、更长序列未测；CH128 的更高收益不外推到其他 C。
4. 原子建图引入 lane 级累加次序不确定（≤1 BF16 ulp 波动，有测试界限）；官方 `index_add_` 同样不确定。
5. 显存：与官方持平（C01–C11）或略降（C12 -47 MiB，来自 FP32 输出缓冲的消除）。不宣传省显存。
6. 冷元数据场景（每次新长度对象）：C08 上优化仍成立（fwd+bwd 1.069），但两侧都要付 metadata 重建与额外 host 同步成本（official 13.22 vs warm 12.70 ms）。
7. V1 仪器开销实测 0.985–0.997×（record_function 无 profiler 时），诊断数字不作为性能结论。

## 统计口径

- 主指标：同进程 AB/BA 配对、5 轮 ×30 计时样本 + 20 预热、每轮中位数、跨轮波动、配对 speedup；P99 不作为指标。
- 暖元数据（同一不可变 cu_seqlens 对象）；冷元数据单列。
- kernel/stage 级数字（如 kernel_v2/v3 文件）仅用于解释机制，不作为完整 Attention 加速结论。
